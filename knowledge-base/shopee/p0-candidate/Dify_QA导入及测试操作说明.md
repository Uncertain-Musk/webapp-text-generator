# Dify QA 导入及测试操作说明

版本：MVP 0.4 Shopee P0 本地候选；生成/核验日：2026-10-11。尚未导入任何 Dify 库，未更改 Workflow、Prompt、模型、环境变量或网站。

## 先审核再导入

本目录是一份独立候选包。仓库原广告 20 条、行业 8 条和来源 28 条未被覆盖；另一批 69 条多站点经营知识不包含在本包中，不应被本包替换。

先阅读《QA覆盖审计报告.md》《Knowledge_Gap.md》和《review.json / changes_and_revision_proposals》。对照表包含 30 条新增与 8 条未应用修订建议。原 A16、A17 等回答仍原样存在，检索可能只召回旧答案并漏掉新条件；不能凭候选包数量增长直接上线。审核人需决定是否批准修订并另行执行，本轮没有应用修订。

两份 QA CSV 只有两列，固定为 `question,answer`：第一列 Question，第二列 Answer。不得使用 General/Policy 五列模板的位置；不得把来源 ID、站点、分类或管理表导入成 Question。新增答案含换行，必须用 CSV 解析器读取，不能按文本行数计数。UTF-8 文件用支持该编码的导入方式打开。

本包提供合并后的全量候选，适合导入一个空的、隔离的测试知识库。不要直接叠加到已有相同 28 条的测试库，否则会形成重复内容；已有环境应先确认文档版本并由管理员选择替换测试文档或新建隔离库。不要删除生产原库或覆盖另一批多站点库。

## 人工导入步骤（尚未执行）

1. 确认当前 Dify 是测试工作区，记录版本、知识库 ID、操作者和时间；本地项目只有通用 DIFY_API_URL / DIFY_API_KEY 配置名，不能证明隔离测试库已连接。
2. 使用该版本支持已有 QA CSV 的导入方式，确认是读取现成 Question/Answer，而非让模型重新生成问答。若版本不支持两列映射，先查该版本文档/模板，不自行调整列序或臆造按钮。
3. 分别上传两份 QA 文件，预览首、中、末及带换行/逗号的记录；确认问题仍是问题，答案没有被分列或截断，尤其 A21、A22、A43、A44、A47 的限制条件与链接完整。
4. 完成索引后核对有效记录 50+8=58。记录知识库、文档与片段 ID，按来源索引建立 QA ID 对照；QA ID 不在导入两列中，不假定系统自动识别 A21 等管理编号。
5. 记录检索方式、Top K、阈值、重排与嵌入模型等现有设置，用固定设置评测。不要为了让分数好看一边改题一边调配置。任何配置变更都需独立记录并重跑受影响题。
6. 此步骤仅说明人工操作。本轮没有创建测试库、上传文件、修改检索节点或生产配置。若需要把新库连接到测试应用，应另行确认授权；不修改现有 Workflow。

## 两层测试与记录

**第一层：真实知识检索。** 在隔离测试知识库的检索测试能力中逐题运行 54 题，保存实际 query、站点上下文、返回片段及分数、完整问题/答案、来源 URL、必要条件是否被截断、文档/片段 ID、时间与配置。仅匹配到相似词不算答对。多来源题如 A44/A47 需要能追溯到相应文档，不以一条错误站点片段替代。

**第二层：最终回答。** 只有已有且确认隔离的测试应用能够使用本批数据、并获准运行时才测试最终回答。记录最终文本、实际引用和是否出现幻觉；知识检索通过不代表模型最终回答通过。不能用线上已连接旧库的 Workflow 回答来证明本候选已通过。

review.json 的 independent_evaluation 中 `actual_result` 目前全部是“未执行”，`retrieved_ids` 与 `actual_answer` 留空。运行后填真实结果，不覆盖原 query/expected_behavior。原40题的旧字段原样保留；本轮判断在 `updated_static_support`、`updated_candidate_qa_ids`、`updated_expected_behavior` 中。旧字段若写“现QA缺...”，仅作为历史基线，按新版预期判断补全效果。

逐题至少判定：正确回答、错误站点引用、遗漏关键条件、指标/归因错误、无来源事实、拒答/知识不足是否恰当。上述维度在 CSV 已给检查标准，不是已执行的结果。

## 必须优先检查的场景

- T08/T41：同商品、Product Ads、时段重叠三项不能漏；暂停不能说成删除，也不能断言其他商品受影响。
- T09/T42：逐商品预算与每日/总额字段；预算额度不是必然花费。
- T20/T47：COD 确认发货与付款不同，Paid/Confirmed 不等于退款后净收入。
- T30/T48：已扣广告毛利不能直接倒数；达目标不等于经济性合格。
- T22/T52：增强出价文档冲突、日均和单次概念；不能拍板未知上限。
- T24/T25/T27/T53：未知站点要明确知识不足，MY计费日不能移植巴西。
- T43/T44/T45：自动加预算剩余次数、编辑限制与投放分开、MY oCPM 与 CPC 指标分开。

人工验收门槛建议：上述 P0 场景不得出现错误站点、遗漏关键条件、错误指标或无来源规则；应拒答题不能捏造事实。所有 54 题必须有执行记录，未执行不计通过；业务支撑题、边界提示题分开统计。T07/T11/T40 等部分支撑题还需补充资格/上下文/项目证据，不能当作全部已覆盖。

## 本地复核与撤回

在仓库根目录运行：`python script/validate-shopee-p0-package.py`。脚本只读取候选文件和原始基线，不调用 API，不修改知识库。自动检查能发现结构、映射和已审查文本漂移，不能自动证明外部事实仍有效。

如隔离测试发现问题，停用本批测试文档并保存失败题与实际片段，保留原库、来源和基线。修正候选后更新对应来源、审查记录及评测，重新走人工审核。不要只刷新日期而不重读来源。生产导入或发布需另行确认；本轮不执行。
