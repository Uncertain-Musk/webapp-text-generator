## 1. 接手时先了解什么

越海首页已从单一聊天页面改为跨境商户经营问题的入口。当前可用链路是：选择任务或直接描述问题 → 通过本站服务端代理调用 Dify Workflow → 流式展示知识问答。

**界面与调用链路可用；政策回答可靠性尚未通过验收。** 不应将工程测试通过理解为知识答案均正确，也不应把首页示例数量理解为知识库覆盖承诺。

真实能力边界：

- AI 后端仅为 Dify 知识助手。项目需求记录的当前模型为千问 3.8，由 Dify 侧管理，前端不切换模型。
- 没有 Amazon、TikTok Shop 等真实店铺 API，没有订单、GMV、库存、结算或广告数据。
- 没有自动操作店铺、复杂 Agent、自动商品合规扫描或可靠的利润广告计算器。
- 当前没有 platform / market metadata filtering；独立经营上下文已传入 Workflow。
- 本次交付源码、知识文件与评测资料，不包含 Dify 管理端配置导出。克隆仓库不能自动恢复远端 Workflow 或知识库。

## 2. 已完成的产品功能

| 模块 | 当前行为与用户需求 |
| --- | --- |
| 首页六类任务 | 查平台规则、处理违规、退款售后、上架合规、平台比较、利润广告，帮助商户判断从哪里开始 |
| 分类问题指引 | 每类 6 个场景问题，共 36 个；展开后包含场景标题、完整问题和建议补充的信息 |
| 示例到输入框 | 点击具体示例才填入并聚焦，用户补充后主动发送；切换或收起分类不覆盖草稿、不触发请求 |
| 直接描述 | “直接描述我的情况”聚焦既有输入框，保留已写内容 |
| 加载与连接恢复 | 参数尚未加载或连接失败时仍可选问题；恢复后自动填入所选示例；编辑或清空问题后填入提示消失 |
| 回答中状态 | 可以继续浏览分类；示例填入和直接描述入口暂时禁用，回答完成后恢复 |
| 经营环境 | 支持 6 个平台及常见站点，可保存、清除、刷新恢复、跨页面保留和跨标签页同步 |
| 问答布局 | 问题在上，分析与建议在下；保留 Markdown、复制、赞踩、失败重试、超时和 Streaming |
| 扩展页面 | `/compliance`、`/issues`、`/tools` 为明确的待开放状态和现有知识问答入口 |

“上架合规”只咨询发布规则和人工核对要点；“利润广告”只咨询指标和核算思路；“平台比较”仍是自然语言问答。页面不会生成假的扫描结果、计算结果或结构化比较数据。

PC 任务区为 3×2，问题清单为双列；390×844 手机任务区为 2×3，问题清单为单列。PC 主标题 34px、区块标题 22px、输入与回答正文 16px；辅助文字 12–13px。沿用现有深绿与浅灰界面。

## 3. 经营上下文与服务端边界

前端保存位置：localStorage 键 `yuehai.operating-environment.v1`。值使用配置中的平台与市场 ID，例如：

```json
{"platform":"tiktok","market":"us"}
```

浏览器向本站 `/api/workflows/run` 提交：

```json
{
  "inputs": {"query":"退款申请需要多久处理？"},
  "platform_context":"TikTok Shop",
  "market_context":"US"
}
```

服务端保留所有已有 inputs，并合并成 Dify 开始节点输入：

```json
{"query":"退款申请需要多久处理？","platform_context":"TikTok Shop","market_context":"US"}
```

没有经营环境时：

```json
{"query":"退款申请需要多久处理？","platform_context":"","market_context":""}
```

旧客户端省略上下文也会补成空字符串；非字符串上下文返回 400。原始 query 不拼接平台名称。比较问题保留明确比较对象，其他适用示例在已选环境时省略重复平台名。

调用链：

```text
site-shell/environment.tsx
→ components/index.tsx → components/result/index.tsx
→ service/index.ts → service/base.ts
→ app/api/workflows/run/route.ts → utils/workflow-context.ts
→ Dify client.runWorkflow → Context / Router → retrieval_query
→ 知识检索 → LLM → SSE → 浏览器
```

Dify 已发布开始节点需声明 `query`、可空的 `platform_context` 与 `market_context`。问题中明确的平台或站点优先于页面环境。当前 Context 节点生成检索用 retrieval_query，不代表检索候选已按 metadata 过滤。

`DIFY_API_URL`、`DIFY_API_KEY` 仅由服务端读取，真实值保存在被 Git 忽略的 `.env.local`。不要改成公开前缀，不要把 SDK 原始异常、Authorization 或密钥写进日志、交接文档或浏览器。当前 Workflow 失败返回脱敏错误，不通过删除上下文字段降级。

## 8. 下一步优先级

1. **Generation：**针对已正确召回的 7 条错误，人工审核回答约束，保留数字、起算状态、资格及例外；环境不足先澄清。此项有真实证据，不将未召回问题笼统归给 Prompt。
2. **Retrieval：**先核对 G0211、G0251、G0281、P0072 等目标分块的启用和索引，再分析 query 与排序；不盲调阈值。
3. **Coverage / 来源：**人工核验退款、举证分支与 ACOS/ROAS 缺口，以及 5 条来源待审项；有真实官方正文和明确适用条件后再改知识库。
4. 每项变更单独记录并使用固定集复测；保留历史证据，不把 UI 完成等同于政策质量通过。

Dify Workflow、模型、知识正文和检索参数由人工管理。接手后先确认授权范围；不要顺带扩展 Agent、店铺 API、metadata filtering、结构化比较或虚假经营数据。
